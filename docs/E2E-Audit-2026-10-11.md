## Repeat the real browser audit

Prerequisites: PostgreSQL on localhost with permission to create disposable
databases, Python 3.14.7 backend environment, existing web dependencies, locally
supplied official `data/`, Chrome and Playwright. Never use a production database.

In the repository root, enter a temporary test password without putting it into
the source or command history. Keep it exported for all three terminals:

```sh
read -r -s CC_E2E_PASSWORD
export CC_E2E_PASSWORD
backend/.venv/bin/python scripts/e2e_server.py --state /private/tmp/sevaro-browser-state.json
```

The launcher creates `cc_browser_e2e_<random>`, pins the official kit, disables
external speech, and binds only localhost:8012. It refuses remote administration
URLs, unrelated saved database names, and state files inside the repository.
Its protected temporary state contains authentication material: do not print or commit it.

In terminal two:

```sh
cd web
API_URL=http://127.0.0.1:8012 npm run dev -- --host 127.0.0.1 --port 5183 --strictPort
```

In terminal three, at repository root with the same password exported:

```sh
export CC_E2E_URL=http://127.0.0.1:5183
export CC_E2E_EMAIL=coord@e2e.local
export CC_E2E_CONFIRM_DISPOSABLE=1
# If needed: export CC_PLAYWRIGHT_MODULE=<path/to/existing/playwright>
node web/scripts/csv-upload.e2e.cjs
node web/scripts/workflows.e2e.cjs
```

Run these scripts in this order against a fresh fixture. They intentionally
mutate test events/offers and require their documented initial state. They do
not reset an existing stream. To check recovery, stop/start the launcher using
the same state and password, then compare authenticated clock, reference
manifest, event count, offers, queue, schedule and upload receipts; preserve an
existing login privately to verify it remains valid. The completed audit performed this comparison.

Stop both temporary servers, then remove only the generated fixture:

```sh
backend/.venv/bin/python scripts/e2e_server.py --state /private/tmp/sevaro-browser-state.json --cleanup
unset CC_E2E_PASSWORD
```
